# WP — IUVENTA cosmetology site (WordPress)

WordPress recreation of the cosmetology clinic landing page
https://iuventa-cosmetology.ru/ (Ювента, Самара). The site is a single-page
landing rendered by a custom theme.

## Project layout

- `wp-content/themes/iuventa/` — the custom theme (version controlled). The
  landing page is `front-page.php`, which pulls section partials from
  `template-parts/` and content from `inc/content.php`.
- `wp/` — WordPress core (git-ignored, downloaded by `bin/setup.sh`).
- `index.php` + `router.php` — front controller and PHP-dev-server router so the
  site is served from the repo root while core lives in `/wp`.
- `bin/setup.sh` — idempotent bootstrap. `bin/serve.sh` — starts the dev server.

## Cursor Cloud specific instructions

- **Stack / services:** This is a single service — a WordPress site running on
  the PHP built-in server. The database is **SQLite** (via the
  `sqlite-database-integration` drop-in), so there is **no MySQL/MariaDB and no
  Docker**. The DB file lives at `wp-content/database/` (git-ignored).
- **System requirements:** `php` (8.x CLI, with `pdo_sqlite`, `mbstring`, `gd`,
  `curl`, `xml`) and `wp-cli` (`wp`) must be on `PATH`. The startup update script
  runs `bin/setup.sh`, which bootstraps WordPress core, the SQLite plugin,
  `wp-config.php`, installs WP and activates the `iuventa` theme. It does NOT
  start a server.
- **Run the site:** `bin/serve.sh` (serves `http://localhost:8080` on
  `0.0.0.0:8080`). This is the dev/run command — do not use a production build.
  Pretty permalinks only work through `router.php`, which `bin/serve.sh` already
  wires up; running a bare `php -S` without the router will 404 on sub-pages.
- **Admin:** `http://localhost:8080/wp/wp-admin/` (note the `/wp` prefix —
  `WP_SITEURL` is `WP_HOME + /wp`, while `WP_HOME` is the bare root). Default
  local credentials: `admin` / `admin123`.
- **Core feature — leads:** the consultation form posts to `admin-post.php`
  (`action=iuventa_lead`) and stores each submission as an `iuventa_lead` custom
  post type. View submissions in wp-admin under **«Заявки»**. A quick check from
  the CLI: `wp post list --post_type=iuventa_lead --path=wp --allow-root`.
- **Lint:** there is no formal test suite. Lint PHP with `php -l <file>` (e.g.
  loop over `wp-content/themes/iuventa/**/*.php`, `index.php`, `router.php`).
- **Editable content (admin):**
  - **Процедуры** and **Косметологи** are custom post types (`procedure`,
    `specialist`) registered in `inc/cpt.php`. Each entry is an editable page;
    `single-procedure.php` / `single-specialist.php` are their page templates,
    with `archive-procedure.php` / `archive-specialist.php` listings. The
    homepage grids (`template-parts/procedures.php`, `doctors.php`) query these
    CPTs and fall back to the static arrays in `inc/content.php` only if empty.
  - The **main page** text (hero, RF-promo, lead form block, clinic contacts)
    is edited in **Appearance → Customize → «Главная страница (Ювента)»**
    (`inc/customizer.php`); templates read it via `iuventa_opt()`.
  - Initial content is **seeded once** from `inc/content.php` on theme
    activation (guarded by the `iuventa_seeded` option). To re-seed from
    scratch: `wp option delete iuventa_seeded` then re-run `bin/setup.sh`.
  - After adding/altering CPTs, flush permalinks: `wp rewrite flush --hard
    --path=wp --allow-root` (also done by `bin/setup.sh`).
- **Gotchas:** `wp/wp-config.php`, `wp-content/db.php` and the SQLite DB are
  git-ignored and regenerated by `bin/setup.sh`; edit `bin/setup.sh` (not the
  generated files) for config changes. `wp-content` is kept in the repo root via
  `WP_CONTENT_DIR`, so the theme is outside the `wp/` core directory on purpose.
